# Мультиязычность: es, de, fr, pt

**Статус:** implemented

## Название фичи

`multilang-es-de-fr-pt` — добавление четырёх новых локалей интерфейса: испанский (es), немецкий (de), французский (fr), португальский (pt) к существующим ru/en.

## Описание проблемы

Приложение поддерживает только русский и английский интерфейс. Для выхода на крупнейшие рынки App Store / Play (Испания, Латинская Америка, Германия, Франция, Бразилия, Португалия) нужны локализованные интерфейсы. Текущая структура `locale.ts` — один файл со словарями ru/en и хардкодом `locale === 'ru'` в `dateUtils.ts` — не масштабируется: добавление каждой новой локали требует правок в нескольких местах, что чревато рассинхронизацией ключей и форматов дат.

## Предлагаемое решение

1. **Бандл локали** — каждый язык выносится в отдельный файл `src/shared/config/locale/<code>.ts`, который экспортирует `LocaleBundle`:
   - `dictionary: LocaleDictionary` — все строки и шаблонные функции
   - `monthsFull` / `monthsShort` — названия месяцев (в родительном падеже для ru)
   - `date: DateLocaleConfig` — порядок день/месяц, разделители, числовой формат даты, `localeTag` для `toLocaleDateString`
2. **Единый реестр** `locale/index.ts`:
   - `Locale` выводится из ключей реестра: `type Locale = keyof typeof bundles`
   - `Record<Locale, LocaleBundle>` заставляет TS компилировать ошибку, если добавлен код без словаря
   - `SUPPORTED_LOCALES`, `dictionaries`, `getDictionary`, `getLocaleBundle`, `getSystemLocale`
3. **`dateUtils.ts` без хардкода** — все ветвления `locale === 'ru'` заменены на данные из `DateLocaleConfig` бандла.
4. **Выбор языка в `SettingsScreen`** — пилюли строятся из `SUPPORTED_LOCALES` (с `flexWrap`), а не из хардкода `['ru', 'en']`.
5. **Детекция системной локали** — `getSystemLocale` ищет язык устройства в `SUPPORTED_LOCALES` (двухбуквенные коды совпадают с языковыми тегами), без per-locale веток.

### Добавление нового языка в будущем

1. Создать `locale/<code>.ts` с бандлом (словарь + месяцы + формат дат)
2. Зарегистрировать в `bundles` в `locale/index.ts`

TS сам проверит полноту словаря и месяцев; тест на паритет ключей поймает рассинхронизацию.

## Влияние на архитектуру

- **Слой:** `shared/config` — локализация остаётся в shared (используется всеми слоями вниз по FSD)
- `locale.ts` → каталог `locale/` (`types.ts`, `<code>.ts`, `index.ts`); публичный API `shared/config/index.ts` не меняется (плюс `getLocaleBundle`)
- `dateUtils.ts` — рефакторинг ветвлений в data-driven конфиг, поведение ru/en не меняется
- `pages/settings/SettingsScreen` — список языков из `SUPPORTED_LOCALES`
- Без новых зависимостей; RTL-языки (ar/he) не поддерживаются этой итерацией

## Альтернативы

1. **Оставить один `locale.ts` на все языки** — файл растёт линейно, но ключи и месяцы всё равно дублируются; нет защиты от неполного словаря, кроме тестов.
2. **i18n-библиотека (i18next)** — полноценная плюрализация и интерполяция, но добавляет зависимость и переписывание всех вызовов `t.*`; текущие шаблонные функции (`deleteChatConfirm(title)`) покрывают потребности.
3. **Только словари без форматов дат** — даты остались бы англоцентричными («January 15» в испанском), что неприемлемо.

Выбран вариант с бандлами: минимальная зависимость, максимальная типобезопасность, добавление языка = 1 файл + 1 строка реестра.

## Оценка сложности

- Время: ~1–2 ч (перевод ~175 ключей × 4 языка + рефакторинг + тесты)
- Риски: умеренные — большой объём ручного перевода (требует ревью носителями), возможное переполнение пилюль выбора языка (решено `flexWrap`)
- Тесты: обновлённые unit-тесты `locale.test.ts` (паритет ключей всех 6 словарей, шаблоны) и `dateUtils.test.ts` (форматы дат новых локалей)
