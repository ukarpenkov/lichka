# Анимация якоря Future Peek: стрелка растёт со свайпом

**Статус:** implemented

## Название фичи

`future-peek-arrow-anim` — якорь жеста История ↔ Будущее раскрывается **по ходу пальца**: сначала растёт длинная стрелка вверх или вниз, и только на пороге появляются часы со стрелкой влево или вправо.

## Описание проблемы

В `ChatRoom` режим **Будущее** открывается overscroll-свайпом вверх у низа истории и закрывается обратным свайпом вниз у верха Future. На пороге (`PEEK_THRESHOLD` = 72px) уже есть haptic и якорь из `future-peek-exit-icons`:

| Направление | Жест | Сейчас на пороге сразу целиком |
|-------------|------|--------------------------------|
| `enter` (история → Future) | pull up у низа | часы + стрелка **вправо** + длинная черта со стрелкой **вниз** |
| `exit` (Future → история) | pull down у верха | длинная черта со стрелкой **вверх** + часы + стрелка **влево** |

Визуал якоря завязан на `pastThreshold`: весь кластер (гайд + часы) имеет `opacity: 0` до порога и вспыхивает целиком после него. Пока палец тянет (`pulling`), на экране только rubber-band ленты — направления перехода не видно.

Ощущение «мертвого» жеста до щелчка: непонятно, куда тянуть и что произойдёт. Нужно progressive disclosure, как в исходном `chat-future-peek`: слабый жест — намёк, сильный — подтверждение.

## Предлагаемое решение

Развести якорь на **две фазы**, синхронизированные с уже существующими `PeekPhase` (`idle` / `pulling` / `armed`). Пороги, haptic, rubber-band, commit и cooldown **не меняются**.

### Что видит пользователь

| Фаза | Палец | Длинная стрелка (гайд) | Часы + стрелка времени |
|------|--------|------------------------|-------------------------|
| A. Тянет | `0 < pull < threshold` | Растёт вместе с пальцем: высота/opacity от 0 до полной | Скрыты |
| B. Порог | `pull ≥ threshold` | Полная длина, остаётся | Появляются (fade + лёгкий scale, как сейчас у кластера) + haptic |
| C. Отпустил до порога | snap-back | Стрелка сжимается обратно | Так и не появились |
| D. Commit | отпуск после порога / auto-commit | Якорь уходит вместе с переходом режима | — |

Направления **как сейчас**, не зеркалить под палец:

- **Enter:** длинная стрелка **вниз** (к Future / compose); на пороге — часы + **вправо**.
- **Exit:** длинная стрелка **вверх** (к истории / шапке); на пороге — часы + **влево**.

«Длинная стрелка» = вертикальная черта 2px + наконечник (`ChevronRight` на `90deg` / `-90deg`), тот же пиксельный язык, без новой иконки.

### Как растёт стрелка

Прогресс `p = clamp(pullDistance / PEEK_THRESHOLD, 0, 1)` на UI thread.

- Высота гайда = `p * maxSpan` (enter: `PEEK_ENTER_GUIDE_SPAN` = 72; exit: текущий слот ~160, рост до той же визуальной полной длины, что сейчас).
- Наконечник сидит на растущем конце (enter — внизу черты, exit — вверху).
- Opacity гайда опережает длину и выходит на полную раньше порога, чтобы направление читалось уже в начале жеста; высота округляется шагом 2px, сохраняя чёткий пиксельный край.
- После порога гайд не растёт дальше; extra-pull до auto-commit (120px) только для rubber-band ленты.

Часы со стрелкой времени — отдельный слой: `opacity`/`scale` только при `armed` (текущий `overlayStyle` кластера). Не едут вместе с ростом черты.

`reduceMotion`: без роста — гайд сразу полной длины при начале pull, часы по-прежнему только на пороге.

### Технически

Всё в `features/chat-future-peek`. Жест уже пишет `pullDistance` и `pastThreshold`; сейчас `overlayStyle` вешается на **весь** кластер.

1. `FuturePeekOverlay` принимает `pullDistance` (SharedValue) и разделяет анимацию на два слоя:
   - новый `guideStyle` — высота/opacity от `pullDistance / PEEK_THRESHOLD`;
   - существующий `overlayStyle` — появление на `pastThreshold`, теперь применяется только к блоку часов.
2. Кластер больше не прячется целиком до порога: гайд виден в `pulling`.
3. `PeekGuide` — анимируемая высота вместо фиксированного `span` / flex на фазе pull.
4. Публичный API слайса: при необходимости проп `pullDistance` на оверлей; `ChatRoomScreen` прокидывает уже существующий `entryPeek.pullDistance` / `exitPeek.pullDistance`.
5. Хелпер прогресса (clamp) — рядом с `peekGestureState`, worklet, с юнит-тестами.

Пороги `PEEK_THRESHOLD` / `PEEK_AUTO_COMMIT` / velocity-commit не трогать. Flick через `threshold * 0.5`: если commit случился до полного роста, стрелка дотягивается spring’ом до полной длины в том же snap, что и rubber-band; часы появляются в момент commit (или на armed, если порог всё же пересекли).

Зависимости только вниз. Новых слайсов нет.

## Альтернативы

| Вариант | Почему не выбран |
|---------|------------------|
| Оставить вспышку всего якоря на пороге | Жест до щелчка без направления; это текущая боль |
| Часы тоже едут/растут с пальцем | Ломает «намёк → подтверждение»: часы = «переход во времени», их место на пороге + haptic |
| Длинная стрелка в сторону пальца (enter вверх) | Конфликт с уже принятыми иконками exit (`future-peek-exit-icons`): enter = вниз, exit = вверх |
| Новая pixel-иконка «длинная стрелка» | Черта + повёрнутый шеврон уже в оверлее |
| Анимация только CSS/layout без SharedValue | Жест живёт на UI thread; высота должна следовать `pullDistance` без JS-кадров |

## Оценка сложности

Средняя-низкая: раскладка оверлея уже разделена на гайд и часы, `pullDistance` есть. Работа — развести стили и анимировать высоту гайда.

Риски:

- Android: рост высоты в том же кадре, что rubber-band списка — проверить 60fps, без layout thrash (предпочесть `height`/`scaleY` на UI thread, не пересчёт flex всего экрана).
- Exit-слот 160px vs enter 72px: рост должен выглядеть одинаково «по пальцу», не выстреливать сразу на 160.
- Empty Future: растущая черта не должна наезжать на «Nothing scheduled yet» сильнее, чем сейчас.
- Тесты оверлея сейчас рендерят оба слоя сразу (`animatedStyle={undefined}`). Нужно покрыть фазы: pulling → только гайд; armed → гайд + часы.

## Статус

**implemented** — гайд растёт в фиксированном слоте вслед за `pullDistance`, часы остаются отдельным threshold-слоем; для `reduceMotion` гайд раскрывается целиком при начале жеста.
