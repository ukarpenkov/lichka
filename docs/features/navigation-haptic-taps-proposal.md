# Короткий haptic на навигацию, модалки и настройки

**Статус:** implemented

## Название фичи

`navigation-haptic-taps` — короткий удар (`impactLight`) на вход и выход из чата, на тапы, которые открывают экраны или модалки, и на тапы в настройках.

## Описание проблемы

В приложении уже есть `hapticTap` / `hapticLongPress` / `hapticSuccess` и флаг `hapticEnabled`. Отдача есть у композера, long-press сообщений, Future Peek и скролла DateTimePicker. Нет отдачи там, где пользователь чаще всего «переходит»:

- тап по чату в списке / поиске / запланированном;
- кнопка назад из чата;
- FAB, поиск, форма чата, контекстное меню, image viewer, пикеры в редакторе;
- строки и переключатели настроек, выбор темы.

Переходы ощущаются «пустыми»: визуал меняется, пальца ничего не подтверждает. Нужен один и тот же минимальный удар, без нового типа haptic.

Gorhom Bottom Sheet в UI не используется (только `BottomSheetModalProvider`). «Окна / bottom sheet» — это `Modal` и вложенные стеки: `ChatForm`, контекстные меню, `AlertDialog`, поиск, DateTime/Period picker, `ImageViewer`, `ThemePicker`.

## Предлагаемое решение

Один примитив: существующий `hapticTap()` → `HapticFeedbackTypes.impactLight`. Срабатывать только на подтверждённый `onPress`, не на свайп и не на программную навигацию (уведомление, виджет, share).

### Что видит пользователь

| Действие | Где |
|----------|-----|
| Вход в чат | строка списка чатов, результат глобального поиска, строка Запланировано |
| Выход из чата | кнопка назад в шапке; Android hardware back во вложенном стеке |
| Открытие оверлея/экрана | FAB, поиск, тап по названию чата, long-press чата, тап картинки, пункты меню Edit/Delete, кнопки даты/периода в редакторе, CTA «запланировать» в Future |
| Настройки | кликабельная строка, Switch, карточка темы, назад из ThemePicker |

Не трогаем: табы пейджера, iOS swipe-back, play/pause голоса, отправку сообщения, скролл пикера, Future Peek, кнопки Cancel/Done внутри уже открытого диалога.

### Как уважается настройка

`shared` не импортирует `entities`. Модульный флаг в `haptics.ts` + `setHapticFeedbackEnabled(boolean)`:

- `hapticTap` / `hapticLongPress` / `hapticSuccess` сами no-op, если выключено;
- `settingsRepository` синхронизирует флаг после чтения/записи;
- `AppInitProvider` читает настройки после миграций, чтобы флаг совпал с БД до первого тапа.

Побочный фикс: экран будильника сейчас дергает haptic без проверки настройки.

### Примитивы UI

- `SettingsRow` — `hapticTap` при `onPress`;
- `Switch` — `hapticTap` перед `onValueChange`;
- `IconButton` — опциональный проп `haptic` (default `false`), чтобы не вибрировать play/pause. Включить на назад, поиск и кнопки композера, которые уже зовут haptic через `onPressIn`.

`AnimatedPressable` не трогаем: им пользуются таббар и будильник.

## Влияние на архитектуру (FSD)

| Слой | Изменение |
|------|-----------|
| `shared` | гейт в `haptics.ts`; `IconButton` / `Switch`; тесты |
| `entities/settings` | sync флага из репозитория |
| `app` | sync при старте; Android `goBack` во вложенном стеке |
| `pages` | список чатов, шапка, поиск, scheduled, настройки, ThemePicker, MessageEditor, контекстное меню |
| `widgets` | FAB-создание через экран списка; ImageMessage; композер без двойного haptic |

Зависимости только вниз. Новых слайсов нет.

## Альтернативы

| Вариант | Почему не выбран |
|---------|------------------|
| Haptic на весь `AnimatedPressable` | Таббар и кнопки будильника получили бы лишний удар; у будильника уже свой `hapticTap`/`hapticSuccess` |
| `IconButton` haptic по умолчанию | Play/pause голоса и закрытие оверлеев не входят в объём |
| `selection` / `impactMedium` для навигации | Запрос — минимальный короткий удар; `impactLight` уже есть |
| Проверка `getSettings()` в каждом обработчике | Дубли и риск забыть; shared не должен импортировать entities |
| Haptic на iOS swipe-back / программный `navigateToChat` | Не тап; удар во время жеста или при открытии из уведомления сюрприз |

## Оценка сложности

Низкая: примитив и настройка уже есть. Работа — гейт флага и точечная проводка.

Риски:

- Двойной удар, если оставить `onPressIn={triggerHapticTap}` у композера и включить `haptic` на `IconButton`.
- Android `goBack` во вложенном стеке не должен срабатывать на iOS swipe-back.
- Тесты, которые мокают только `getSettings`, не отключат новый гейт — мокать `haptics` или `setHapticFeedbackEnabled`.
