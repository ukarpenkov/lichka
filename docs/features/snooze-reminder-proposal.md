# Отложенная копия обычного уведомления

**Статус:** implemented — поведение запрошено пользователем и реализовано.

## Название фичи

«Отложить на час» и «Отложить на день» в меню пришедшего уведомления.

## Описание проблемы

Пришедшее обычное уведомление нельзя быстро повторить позже, сохранив исходное сообщение в истории.

## Предлагаемое решение

Для `reminder` с `scheduledAt <= now` добавить два пункта долгого нажатия. Создавать новое одноразовое уведомление в том же чате с новым ID и временем на 60 минут или 24 часа позже нажатия. Сохранять текст, чек-лист и вложение; файл вложения копировать отдельно, чтобы удаление одного сообщения не затрагивало другое. Исходное сообщение не менять. Использовать существующий планировщик и обновлять Future; Scheduled читает новые записи при открытии. Ошибку показывать в диалоге. Будильники, периодические напоминания и обычные заметки не включены.

## Влияние на архитектуру

- `features/notifications`: проверка доступности и создание отложенной копии через публичный API сущности.
- `pages/chat-room`: меню, вызов действия и обновление данных.
- `shared/config/locale`: подписи для шести языков.

## Альтернативы

- Перенос исходного сообщения убирает его из истории и противоречит запросу.
- Выбор произвольной даты добавляет лишние шаги. Выбраны два фиксированных интервала.

## Оценка сложности

Низкая, около 2–3 часов. Риски: общий файл вложения, повторное нажатие, ошибки сохранения и расчёт времени от старого уведомления. Тесты проверяют интервалы от момента действия, неизменность оригинала, отдельное вложение, ограничения типов и работу меню.
