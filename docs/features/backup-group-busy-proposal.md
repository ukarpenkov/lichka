# Блокировка группы Backup на время долгой операции

**Статус:** implemented

## Название фичи

`backup-group-busy` — пока идёт долгая операция бэкапа (Google Drive / файл), вся группа Backup в настройках заблокирована, а на нажатой строке крутится лоадер в цвете текста темы.

## Описание проблемы

В Settings четыре действия в секции Backup:

| Действие | Что делает |
|----------|------------|
| Backup to Google Drive | ZIP во временный файл + OAuth + upload в Drive |
| Restore from Google Drive | OAuth + download + диалог режима + импорт |
| Export to file | сборка ZIP с медиа на диск |
| Import from file | диалог режима + DocumentPicker + импорт ZIP/JSON |

Все они асинхронные и могут занимать секунды (сеть, файлы, системный пикер). Сейчас строки остаются активными: можно нажать вторую операцию поверх первой, получить гонку по БД/файлам и не понять, какое действие ещё выполняется.

## Предлагаемое решение

Один эксклюзивный слот на всю группу Backup.

### Что видит пользователь

1. Нажал одну из четырёх строк — сразу:
   - на **этой** строке справа появляется `ActivityIndicator` цвета `colors.ink` (тот же ink, что у текста строки);
   - остальные три строки дизейблятся (muted, без нажатия и haptic).
2. Слот держится на всём сценарии действия, включая подтверждающие диалоги и системный пикер. Отмена (диалог, back, отмена Google Sign-In / DocumentPicker) снимает лоадер и снова включает группу.
3. Диалог успеха/ошибки показывается **после** снятия busy — кнопки Backup снова доступны.

### Технически

1. Слайс `features/backup-group-busy`: хук `useBackupGroupBusy`.
   - `activeAction`: какая строка сейчас занята (`driveBackup` / `driveRestore` / `exportFile` / `importFile` | `null`).
   - `run(action, task)` — ставит слот, `await task()`, в `finally` снимает; повторный `run` пока слот занят — no-op.
   - Реэнтрантность через ref, чтобы два быстрых тапа не прошли до ре-рендера.
2. `pages/settings/SettingsRow`: пропы `disabled` и `loading`. Лоадер — маленький `ActivityIndicator`, `color={colors.ink}`. Заблокированная (не loading) строка — muted icon/text, без haptic.
3. `SettingsScreen`: все четыре обработчика Backup оборачиваются в `run(...)`. Диалоги выбора merge/replace для restore и import — promise-based, чтобы `run` дожидался конца сценария, а не только первого `await`. Отмена restore после скачивания удаляет temp-файл.

Пороги, формат ZIP/JSON, Drive API и тексты локализации **не меняются**.

## Влияние на архитектуру (FSD)

| Слой | Изменение |
|------|-----------|
| `features/backup-group-busy` | новый слайс: хук эксклюзивного слота + тесты |
| `pages/settings` | `SettingsRow` (loading/disabled), обработчики Backup в `SettingsScreen` |
| `widgets` / `entities` / `shared` / `app` | без изменений |

Зависимости только вниз. Public API слайса — `index.ts`.

## Альтернативы

| Вариант | Почему не выбран |
|---------|------------------|
| Дизейблить только нажатую строку | Можно запустить export во время Drive upload — гонка по тем же данным |
| Полноэкранный оверлей / блокировка всего Settings | Лишнее: тема, язык, звук не конфликтуют с бэкапом |
| Текст «Loading…» вместо крутилки | Хуже читается в строке; крутилка уже принятый паттерн (`ChatForm`, `ChatRoom`) |
| Лоадер в акценте/destructive | Пользователь просил цвет темы «как текст» = `colors.ink` |
| Снимать busy на время диалога | Между fetch и импортом снова можно нажать соседнюю кнопку |

## Оценка сложности

Низкая: операции уже есть, меняется только UI-слот и пропы строки.

Риски:

- Вложенные диалоги merge → replace: `AlertDialog` закрывается через `onClose` сразу после кнопки — нельзя сбрасывать busy в общем `onClose`, только через settled promise (повторный settle — no-op).
- Отмена Google Sign-In / DocumentPicker должна снимать слот без диалога ошибки (как сейчас).
- Unmount экрана во время upload: `finally` не должен `setState` после размонтирования.

**implemented** — эксклюзивный слот на группу Backup, лоадер ink на активной строке, отмена снимает busy.
