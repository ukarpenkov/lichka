# Скрывать sticky-дату, пока виден разделитель дня

**Статус:** implemented

## Название фичи

Не дублировать метку дня в шапке ленты, пока inline-разделитель (`── Вчера ──` / `── Сегодня ──`) ещё на экране.

## Описание проблемы

В истории чата дата рисуется дважды:

1. **Inline `DateSeparator`** — строка в ленте над первым сообщением дня.
2. **Sticky overlay** — абсолютный чип под `ChatHeader`, который должен подсказывать день при скролле длинной истории.

На коротком чате (или когда разделитель дня ещё в зоне просмотра) обе метки видны сразу: сверху пустой области «── Вчера ──», и та же строка прямо над сообщениями. Sticky не несёт информации и выглядит как баг.

Ожидание: sticky появляется **только после того**, как «свой» разделитель уехал вверх.

## Предлагаемое решение

Чистая функция `resolveStickyDate(viewableItems)` для inverted + reversed ленты (наибольший viewable index = визуальный верх):

| Состояние визуального верха | Sticky |
|-----------------------------|--------|
| Верхняя строка — `DateSeparator` | скрыт |
| Верх — сообщение, разделитель **этого** дня ещё viewable | скрыт |
| Верх — сообщение, разделитель этого дня уже уехал | показать день сообщения |
| На экране ещё разделитель **другого** (более нового) дня | не мешает: sticky = день верхней строки |

Порог viewability для даты снижен до `itemVisiblePercentThreshold: 1`, чтобы чип не всплывал, пока метка в ленте почти не исчезла. Смена sticky по календарному дню (`sameStickyDay`), а не по полному ISO — без лишнего FadeIn на том же дне.

Режим Future (`── Будущее ──`) не меняется: это индикатор режима, не дата.

## Влияние на архитектуру (FSD)

| Слой | Изменение |
|------|-----------|
| `pages/chat-room` | `stickyDate.ts` + `ChatRoomScreen` (`onViewableItemsChanged`) |
| `features` / `entities` / `shared` | без изменений |

Зависимости только вниз. Public API слайса не расширяется.

## Альтернативы

| Вариант | Почему не выбран |
|---------|------------------|
| Убрать sticky совсем | Теряется ориентир дня в длинной истории, когда разделитель уже за краем |
| Sticky выталкивается входящим разделителем (как Telegram) | Сложнее (геометрия/анимация); пользователь явно выбрал hide-until-offscreen |
| Скрывать sticky только если контент не скроллится | Не покрывает длинную ленту, где разделитель ещё внизу экрана |

## Оценка сложности

Низкая: одна чистая функция + правка callback viewability. Риск: `onViewableItemsChanged` на быстром скролле может кратко мигнуть чипом — порог 1% это смягчает.
