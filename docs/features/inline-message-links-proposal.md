# Ссылки в сообщениях (иконка + переход)

**Статус:** implemented

## Описание проблемы

Текст сообщения — сплошная строка. URL из «Поделиться» или набранный вручную выглядит как обычный текст: нет признака, что это ссылка, и нет способа открыть её одним нажатием. Приходится копировать адрес и вставлять в браузер.

Нужный сценарий:

1. После текста каждой ссылки — пиксельная иконка `link` (высота как у шрифта сообщения).
2. Нажатие на **текст** URL открывает ссылку во внешнем браузере.
3. Share: URL уже полный — иконка видна сразу, как только сообщение оказалось в ленте.
4. Ручной ввод: иконка не должна «прыгать» на каждом символе, пока адрес ещё печатают.

## Предлагаемое решение

Ссылки **не храним отдельно** — это по-прежнему обычный `message.body`. Распознавание при отрисовке.

### Как выглядит

В теле сообщения (и в подписи к картинке) URL подчёркнут цветом текста, сразу после него — Streamline Pixel `interface-essential-link`. Размер иконки = `fontSize` строки (16 в ленте, 14 в подписи к фото). Тап по тексту URL или по иконке → `Linking.openURL`. Долгое нажатие на строку по-прежнему открывает меню (копировать / изменить / удалить).

В поле ввода иконки **нет**: `TextInput` не умеет нормально вставить inline-SVG после символа, и иконка скакала бы при дописывании пути (`https://site.com` → `/blog` → `/post`).

### Share vs ручной ввод (UX)

| Как URL попал в чат | Когда считается готовым | Что видит пользователь |
|---------------------|-------------------------|------------------------|
| «Поделиться»        | Строка уже полный `http(s)://…` или `www.…` | После Send иконка сразу: URL в конце сообщения **не** требует пробела после себя |
| Вставка из буфера   | То же, если адрес полный | Как share |
| Печать вручную      | Иконка только **после отправки** и только если URL полный | Пока человек печатает в композере — ничего не мигает. Обрывки `https://`, `www.`, `https://git` без точки в хосте **не** становятся ссылкой даже после Send |

Полный URL:

- схема `http://` / `https://` **или** префикс `www.`;
- хост: `localhost`, IPv4, либо имя с точкой (`example.com`);
- хвостовые `. , ; : ! ? ) ] }` и кавычки отрезаются, если скобки не парные (`wiki/Foo_(bar)` не ломаем).

Не линкуем: `javascript:`, `file:`, голые `example.com` без схемы (слишком много ложных срабатываний: `file.txt`, инициалы).

### Технически

`parseMessageLinks(text)` режет строку на сегменты `text | link`. `LinkifiedText` рисует их nested `Text` + пиксельная иконка. Открытие — только `http:` / `https:`.

## Альтернативы

| Вариант | Почему не выбран |
|---------|------------------|
| Иконка внутри композера на каждом символе | Прыгает при дописывании path; `TextInput` не держит inline-icon |
| Иконка в композере после паузы / пробела | Дублирует текст поля отдельным chrome, легко разъехаться с переносами |
| Линковать `example.com` без схемы | Ложные срабатывания |
| Хранить links в payload | Лишняя схема, рассинхрон при редактировании |
| Синий «веб» цвет вместо иконки | Ломает дуотон темы; иконка уже есть в наборе |
| Тап по всей строке сообщения открывает первую ссылку | Нельзя нажать «мимо» ссылки; конфликтует с будущими жестами |

## Оценка сложности

Невысокая: чистый парсер + один UI-компонент + подстановка в местах, где уже рисуется `message.body`. Риски: жест длинного нажатия vs тап по nested `Text`; выравнивание SVG внутри строки на Android.

## Ограничения

- Иконки нет в `TextInput` (композер и редактор сообщения).
- Поиск по чату / глобальный поиск по-прежнему ведут в сообщение, а не в браузер.
- Голый домен без `http`/`www` не линкуется.
- iOS/Android открывают системный браузер (или приложение-обработчик http).
