# Заглянуть в будущее чата (Chat Future Peek)

**Статус:** draft

## Название фичи

`chat-future-peek` — режим «будущее» внутри экрана чата: одним жестом (overscroll вниз у низа ленты) пользователь переключает ту же комнату с истории на список запланированных сообщений этого чата — и так же легко возвращается назад.

Короткое имя в UI / копирайте: **Будущее** / **Future**.

---

## Описание проблемы

### Контекст продукта

Lichka — чат с самим собой, где ядро ценности — не только история, а **сообщения во времени**: reminders, alarms, periodic. Сегодня запланированное живёт в отдельном табе **Scheduled** (глобальный список по всем чатам), а лента `ChatRoom` показывает только уже «доставленное» прошлое.

### Job-to-be-done

> Когда я уже в чате и думаю «что я себе тут напланировал?», я хочу мгновенно увидеть будущее **этого** чата — не покидая контекст разговора.

### Боль сейчас

| Шаг | Что делает пользователь | Friction |
|-----|-------------------------|----------|
| 1 | Читает / пишет в чате | — |
| 2 | Хочет проверить планы по этому чату | Контекст «здесь» |
| 3 | Уходит на таб Scheduled | Потеря шапки чата, аватара, названия |
| 4 | Ищет нужный чат в общем списке | Сканирование, фильтр глазами |
| 5 | Тапает → снова ChatRoom | Сейчас открывается **история**, а не «будущее»; для reminder/alarm будущие в ленте не видны |

Итог: проверка планов — **3–4 тапа + смена контекста**, хотя вопрос локальный: «что в этом чате впереди?».

### Почему это важно именно для Lichka

В мессенджерах (Telegram, WhatsApp) scheduled — вспомогательная функция «отправить позже». В Lichka запланированное — **первая скрипка продукта**: записка из настоящего в будущее. Жест «заглянуть вперёд» усиливает метафору и делает продукт узнаваемым, а не «ещё одним списком напоминаний».

---

## Цели и non-goals

### Goals (MVP)

1. Из `ChatRoom` одним жестом открыть ленту будущего **только текущего** чата.
2. Сохранить шапку чата (аватар, название) — не уводить на другой экран/таб.
3. Явно показать, что режим сменился (индикатор «Будущее»).
4. Легко выйти: жест вверх / «назад» в шапке.
5. Из таба Scheduled тап по записи открывает **этот же чат уже в режиме будущего**, с фокусом на выбранном сообщении.
6. Пустое будущее — честный empty state с CTA «Запланировать».

### Non-goals (MVP)

- Не заменять и не удалять глобальный таб Scheduled (он нужен для обзора **всех** чатов).
- Не смешивать историю и будущее в одной бесконечной ленте.
- Не менять модель доставки / notification scheduling.
- Не делать жестом создание scheduled (только навигация в режим просмотра).
- Не требовать отдельный экран в стеке навигации как «новую страницу продукта» — это **режим комнаты**, не новый destination в IA.

## Предлагаемое решение

### Ментальная модель (как в сильных мессенджерах)

Два режима одной комнаты:

| Режим | Что на экране | Аналогия |
|-------|---------------|----------|
| **История** (default) | Доставленные сообщения, новые снизу | Обычный chat thread |
| **Будущее** | Только enabled scheduled этого чата: reminder / alarm / periodic | Telegram «Scheduled Messages» **внутри** чата, не глобальный inbox |

Пользователь не «уходит в другое приложение» — он **переворачивает** тот же чат во времени.

### Entry: жест overscroll вниз

Паттерн близок к pull-to-refresh / overscroll в нативных чатах, но с другим смыслом: не «обновить», а «выйти за край настоящего».

**Предусловия срабатывания**

1. Пользователь в `ChatRoom` в режиме **История**.
2. Лента уже у **нижнего края** (`at bottom` / cannot scroll further down). Если не внизу — свайп вниз = обычный скролл, триггер **не** активируется.
3. Жест — **длинный** overscroll вниз (тянет контент / rubber-band за низ).

**Прогрессия жеста (best practice: progressive disclosure + confirmation)**

| Фаза | Порог | Feedback |
|------|-------|----------|
| A. Тянет | ниже порога | Лёгкий rubber-band, без хаптика и без иконки |
| B. Порог пройден | `pullDistance ≥ threshold` | Короткий haptic «щелчок» + появляется якорь: **часы со стрелкой вперёд** |
| C. Commit | отпускание пальца **после** порога *или* дотягивание до auto-commit | Переход в режим **Будущее** |

Хаптик и иконка — **только после порога**, чтобы не было случайных срабатываний (как у Telegram: сильный жест подтверждается, слабый — нет).

### Что видит пользователь в режиме «Будущее»

- **Та же шапка:** аватар + название чата.
- **Индикатор режима** (обязателен): подзаголовок / chip / замена sticky-даты на «Будущее» / Future — чтобы нельзя было перепутать с историей (паттерн Telegram: отдельный список Scheduled с ясным заголовком).
- **Список:** карточки/бабблы запланированных с понятным «когда»:
  - одноразовые: «завтра в 9:00», «15 августа, 08:00»;
  - periodic: «каждый час», «каждый день в …».
- Сортировка MVP: по ближайшему срабатыванию (ascending) — как ожидают от «что дальше».
- Composer: **скрыт или заблокирован** в MVP (режим просмотра планов; создание — через существующий CTA / empty state). Решение зафиксировать на approve.

### Exit

Любой из способов (оба в MVP):

1. **Свайп вверх** с верхнего края списка будущего / симметричный overscroll вверх → возврат в **Историю** (с haptic на пороге, зеркально entry).
2. **Назад в шапке** → выход из режима будущего; если стек позволяет — поведение «как назад из режима», без неожиданного ухода на ChatList, пока пользователь явно не выходит из комнаты.

После выхода — снова история; scroll position истории **желательно** восстановить (как WhatsApp сохраняет позицию при возврате в чат).

### Deep link из таба Scheduled (обязательный сценарий)

Сейчас тап по scheduled открывает `ChatRoom` в **истории**, где будущего часто не видно — это ломает ожидание «я тапнул план → хочу его увидеть».

**Новое поведение**

Тап по элементу в `ScheduledScreen` → `ChatRoom` того же `chatId` **сразу в режиме Будущее**, с:

- фокусом / scroll к выбранному `messageId`;
- краткой подсветкой (highlight pulse), как при jump-to-message в Telegram / WhatsApp search.

| Тип | Поведение |
|-----|-----------|
| reminder / alarm | Открыть future mode + highlight этой записи |
| periodic | То же: future mode + highlight шаблона periodic (не display-fire в истории) |

Параметр навигации (концепт): `mode: 'future' | 'history'` + существующий `messageId` / `focusNonce`.

Глобальный таб Scheduled остаётся **обзором всех чатов**; Future Peek — **локальный взгляд внутри комнаты**. Они дополняют друг друга (WhatsApp: Starred / Links vs открытие чата).

### Empty state

Если в чате нет ни одного enabled scheduled:

- После жеста / deep link — пустой экран будущего с копирайтом в духе: **«Здесь пока ничего не запланировано»**.
- Primary CTA: **«Запланировать»** → открывает существующий flow создания reminder/alarm/periodic в этом чате.
- Secondary: остаться / выйти жестом или «назад».

Пустой future **не** считается ошибкой жеста — жест успешен, контента нет.

### Граничные случаи

| Кейс | Поведение |
|------|-----------|
| Не у низа ленты | Overscroll-триггер выключен; обычный скролл |
| Тянул, но отпустил до порога | Возврат rubber-band, режим не меняется |
| Во время анимации перехода | Игнорировать повторный жест / debounce |
| Клавиатура открыта | Entry-жест peek отключён (иначе pan конфликтует с фокусом `Message...`); после закрытия клавиатуры жест снова доступен. При commit в Future по-прежнему `Keyboard.dismiss` |
| Сообщение сработало, пока пользователь в Future | Список обновляется; сработавшее исчезает из будущего (как Scheduled refresh) |
| Удалили / отключили запись в Future | Убрать из списка; при пустом → empty state |
| Android system back | Как «назад» шапки: сначала выход из Future, потом pop ChatRoom |
| Горизонтальный свайп табов | Не конфликтовать: на `ChatRoom` pager табов уже отключён; вертикальный жест — локальный |
| Deep link на удалённый `messageId` | Открыть Future без highlight; optional soft toast |

## Пользовательские сценарии (acceptance)

1. **Peek из истории:** внизу чата → длинный pull down → haptic + иконка часов вперёд → отпускает → видит Future этого чата + индикатор режима.
2. **Выход жестом:** в Future → swipe up / overscroll up → снова История, позиция сохранена.
3. **Выход назад:** в Future → back в шапке / system back → История (не ChatList с первого back).
4. **Пусто:** нет scheduled → Future empty + «Запланировать».
5. **Из Scheduled:** тап по reminder → ChatRoom Future + scroll/highlight этой записи.
6. **Ложный жест:** скролл не у низа → Future не открывается.
7. **Порог:** короткий pull → нет haptic/иконки/перехода.

## Competitive / UX references (международные практики)

| Паттерн | Где | Что берём | Что не копируем слепо |
|---------|-----|-----------|------------------------|
| Scheduled Messages **внутри чата** | Telegram | Локальный список планов комнаты, не только глобальный inbox | Отдельный экран «Scheduled» как push в стеке — у нас режим той же комнаты |
| Jump + highlight | Telegram / WhatsApp search | Deep link из Scheduled с подсветкой | — |
| Overscroll / rubber-band + threshold | iOS Mail, Telegram pull | Подтверждение жеста порогом + haptic | Не делать pull-to-refresh: смысл другой |
| Режим vs новый экран | Instagram «Close Friends» / Stories archive feel | Одна шапка, смена содержимого | Не прятать режим без индикатора |
| Empty + CTA | WhatsApp / Telegram empty chats | Честный empty + действие | — |

**Product principle:** жест = short cut к уже существующей сущности (scheduled этого чата), а не новая сущность данных.

## Метрики успеха (после ship)

- Доля сессий `ChatRoom`, где открыли Future ≥ 1 раз.
- Доля входов в Future **жестом** vs **из Scheduled**.
- Bounce: открыл Future и вышел &lt; 2 сек без взаимодействия (слишком случайный жест?).
- Конверсия empty CTA «Запланировать».
- Жалобы / отмены: ложные срабатывания overscroll.

## Предлагаемое решение (технический контур)

Высокоуровнево (детали реализации — после approve):

1. **Состояние режима** в `ChatRoom`: `timelineMode: 'history' | 'future'`.
2. **Данные Future:** выборка scheduled **по `chatId`** (подмножество логики `getScheduledMessages` / новый `getScheduledMessagesByChatId`).
3. **Жест:** Reanimated + Gesture Handler overscroll у низа FlatList; threshold + haptic + overlay icon.
4. **Навигация:** расширить params `ChatRoom`: `mode?: 'future'`, сохранить `messageId` / `focusNonce` для highlight.
5. **ScheduledScreen:** `navigateToChat(chatId, messageId, { mode: 'future' })` для всех типов scheduled (не только periodic).
6. **UI:** индикатор в header / sticky area; empty state; опционально скрыть composer в Future.

## Альтернативы

| Вариант | Плюсы | Минусы | Решение |
|---------|-------|--------|---------|
| A. Режим внутри ChatRoom + overscroll (этот proposal) | Контекст чата, «магия», deep link из Scheduled осмыслен | Сложность жеста, конфликт со скроллом | **Выбран** |
| B. Кнопка в шапке «Будущее» без жеста | Просто, discoverable | Нет wow; лишний chrome; жест — DNA фичи | Отклонён как единственный entry; кнопка — optional later для discoverability |
| C. Push отдельного `ChatFutureScreen` | Чистый стек | Ломает «та же шапка / тот же чат»; тяжелее back | Отклонён |
| D. Смешать future в одну ленту с датами «Завтра» | Один скролл | Путает прошлое/будущее; ломает «новые снизу» | Отклонён |
| E. Только улучшить Scheduled tab | Меньше кода | Не решает JTBD «уже в чате» | Отклонён как замена; таб остаётся |

**Discoverability (фаза 2, optional):** тихий affordance в шапке или one-time coach mark «Потяните вниз у низа чата» — без обязательности для MVP, если жесты + deep link из Scheduled покрывают основные входы.

## Оценка сложности

| Часть | Оценка |
|-------|--------|
| Режим + список + empty + индикатор | 0.5–1 дн |
| Overscroll жест + haptic + icon | 1–1.5 дн |
| Навигация Scheduled → Future + highlight | 0.5 дн |
| Locale, a11y, тесты | 0.5–1 дн |
| **Итого MVP** | **~3–4 дня** |

### Риски

- Конфликт overscroll с `inverted` / `scrollToEnd` ленты чата.
- Ложные срабатывания → строгий `atBottom` + высокий threshold + haptic только post-threshold.
- Ожидание «создать сообщением» в Future — держать composer policy явной.
- Regression: periodic highlight из Scheduled сейчас ведёт в историю; поведение меняется осознанно.
