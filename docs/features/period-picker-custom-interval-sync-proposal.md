# Синхронизация custom interval с пресетами PeriodPicker

**Статус:** implemented

## Название фичи

`period-picker-custom-interval-sync` — при выборе дефолтного интервала на кнопках PeriodPicker визуально заполнять поле «Custom interval» пересчётом в минуты.

## Описание проблемы

В модалке периодичности (`PeriodPicker`) есть пресеты («Every 5 min», «Every hour», …) и отдельное поле custom interval в минутах. При выборе пресета поле custom очищалось — пользователь не видел, сколько минут соответствует выбранному интервалу (особенно для «Every hour» / «Every day»).

## Предлагаемое решение

При выборе пресета и при открытии пикера с уже выбранным пресетным значением записывать в поле custom interval число минут пресета:

| Пресет | Значение в поле (мин) |
|--------|------------------------|
| Every 5 min | `5` |
| Every 10 min | `10` |
| Every 15 min | `15` |
| Every hour | `60` |
| Every day | `1440` |

Единица поля остаётся минутами; меняется только визуальное заполнение. Логика подтверждения (`selected ?? customMinutes`) без изменений: пресет по-прежнему приоритетен, ручной ввод снимает выделение с кнопок.

## Влияние на архитектуру

- **Слой:** `widgets/period-picker` — локальное UX-изменение в `PeriodPicker.tsx`
- Без новых слайсов, API и зависимостей
- Public API виджета не меняется (`visible` / `value` / `onConfirm` / `onCancel`)

## Альтернативы

1. **Показывать суффикс единицы пресета (h / d)** — ломает контракт «custom всегда в минутах» и усложняет парсинг.
2. **Отдельная подпись «= N min» рядом с пресетом** — дублирует информацию и загромождает список.
3. **Не заполнять поле, оставить как было** — хуже UX: неочевидный пересчёт hour/day → минуты.

Выбран вариант с заполнением минут: минимальное изменение, совпадает с единицей custom-поля.

## Оценка сложности

- Время: ~5–10 мин
- Риски: минимальные — только UI-state (`setCustomText`), без изменений хранения и нотификаций
