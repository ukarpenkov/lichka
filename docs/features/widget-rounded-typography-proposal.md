# Скругление, шрифты и событийное обновление виджета

**Статус:** approved — пользователь разрешил реализацию при сохранении 3D-эффекта и производительности.

## Название фичи

Скругление Android-виджета как в календаре, шрифты приложения и экономное обновление.

## Описание проблемы

Радиус Lichka — 16dp, у виджета календаря — 36dp. Текст виджета использует системный sans-serif вместо JetBrains Mono и Press Start 2P. Любой snapshot заново рисует и записывает PNG фона, даже когда изменился только список. Дополнительно включено обновление каждые 30 минут.

## Предлагаемое решение

- Радиус 36dp, прежние сплошная рамка 2dp и смещённая тень 4dp; радиус ограничен размером маленького виджета.
- Нативные TextView с системным `monospace` для прокручиваемого списка. Лаунчер создаёт restricted context, в котором TextView не загружает пользовательские файлы шрифтов (проверено в исходниках Android TextView/RemoteViews).
- Пустое состояние — настоящий Press Start 2P из assets приложения, 16sp с уменьшением до 10sp на маленьких размерах; только эта статичная надпись рендерится в прозрачный PNG и кэшируется по тексту, цвету, размеру и масштабу шрифта. ImageView содержит contentDescription для доступности.
- Отступы учитывают увеличенные углы; строки остаются нативным текстом. Суммарный бюджет bitmap fallback фона и надписи ограничен 832 КБ до служебных данных RemoteViews.
- PNG фона кэшируется по размеру, плотности, цветам и версии оформления. У разных вариантов разные URI; хранится ограниченное число вариантов. Без изменения оформления PNG не создаётся повторно.
- Изменения данных обновляют только адаптер списка; одинаковые snapshots не инициируют перерисовку. Тема, язык, добавление и resize обновляют RemoteViews целиком. Сохраняются coalescing и повторная отправка темы при сворачивании.
- На API 31+ используются `RemoteCollectionItems` вместо legacy service adapter: это исключает воспроизведённую на новом Android гонку между async-конвертацией старого списка и сменой темы. На API 24–30 остаётся сервис. Внутри snapshot bitmap трёх типов иконок переиспользуются; длины строк для однострочного представления ограничены для небольшого Binder payload.
- Периодическое обновление отключается. Системные события времени/перезагрузки и срабатывание существующих напоминаний обновляют данные без нового периодического таймера.

## Влияние на архитектуру

Существующий слайс `src/features/scheduled-widget` остаётся точкой синхронизации JS. Представление RemoteViews и кэш остаются в нативном Android-адаптере. Новые зависимости между FSD-слоями не добавляются.

## Альтернативы и обоснование выбора

- Bitmap всего виджета: лишняя отрисовка, хуже доступность и прокрутка.
- JetBrains Mono в каждой строке через bitmap: точное совпадение гарнитуры ценой рендеринга строк и дополнительного IPC; выбран нативный консольный monospace для производительности.
- Сохранить периодический polling: не обеспечивает своевременного обновления, расходует ресурсы при неизменных данных.

## Оценка сложности

Небольшое изменение внешнего вида; средняя сложность проверки обновлений и кэша (несколько часов с проверкой на Android). Основные риски — кэширование URI лаунчером, компактные размеры, особенности обновления коллекции при смене темы. Проверки: JVM-тесты кэша/геометрии, существующие Jest-тесты синхронизации, сборка debug и визуальная проверка RemoteViews при наличии эмулятора.
