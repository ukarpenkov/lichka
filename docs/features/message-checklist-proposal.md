# Списки с галочками в сообщениях

## Название фичи
Чек-лист из строк сообщения.

## Описание проблемы
Многострочные сообщения, например список покупок, нельзя отмечать по пунктам. Нужен явный переключатель списка в поле ввода и сохранение выполненных пунктов после отправки.

## Предлагаемое решение
- После первого переноса строки показывать слева от скрепки кнопку с пустым пиксельным чекбоксом. Повторное нажатие выключает режим, сохраняя текст.
- В режиме списка показывать пустые чекбоксы у каждой логической строки, включая текущую пустую. Автоматический перенос длинного текста не создаёт новый пункт. До отправки пункты нельзя отметить.
- При отправке сохранять непустые строки как упорядоченные пункты со стабильными `id`, текстом и `checked`. Пустые строки и завершающий Enter не создают пустые задачи.
- В отправленном сообщении нажатие переключает галочку и зачёркивание текста; повторное нажатие снимает отметку. Изменения сразу записываются в SQLite и сохраняются при повторном открытии чата.
- Добавить nullable-поле `messages.checklist` с JSON-массивом пунктов: `NULL` означает обычное сообщение, массив — список. Текст `body` остаётся доступен поиску, копированию, превью и уведомлениям. Миграция не меняет старые сообщения.
- Использовать готовую `Check` из Streamline Pixel и квадратную рамку на той же сетке. Существующие иконки не менять.
- При редактировании сохранять отметки неизменённых пунктов, новые/переименованные пункты считать невыполненными. Поддержать список в подписи к изображению и в напоминаниях.
- Включить данные списка в существующий экспорт/импорт JSON/ZIP (версия формата 3, чтение версий 1–3). Отдельный механизм резервного копирования не добавлять.

## Влияние на архитектуру
- `shared/db`: миграция SQLite; `shared/ui/pixel`: иконки.
- `entities/message`: тип пункта, преобразование/проверка списка, чтение и запись состояния.
- `features/message-checklist`: переключение отправленного пункта и UI списка, public API в `index.ts`.
- `features/retro-text-caret`: необязательные маркеры начала логических строк, синхронизированные с переносом и прокруткой единого поля ввода.
- `widgets/message-composer`: кнопка режима и отправка; `widgets/image-message`: слот подписи.
- `pages/chat-room`: вывод списка и обновление после отметки; существующий редактор продолжает работать с текстом.
- `features/export`, `features/import`: совместимость сохранённых данных.

## Альтернативы и обоснование выбора
- Символы `☐` в тексте: портят копирование и зависят от шрифта; вместо них отдельные пиксельные иконки.
- Отдельный TextInput на каждый пункт: усложняет вставку текста, выделение и работу Enter; сохраняем единое поле.
- Новый тип сообщения: конфликтует с напоминаниями и изображениями; nullable-поле позволяет совмещать возможности.
- Таблица пунктов: для локальных коротких списков избыточна; JSON хранится атомарно вместе с сообщением.

## Оценка сложности
Средняя, ориентировочно 4–6 часов. Основные риски: выравнивание чекбоксов при переносе/прокрутке текста, сохранение состояния при редактировании, совместимость старых резервных копий. Покрыть сценарии unit/integration-тестами, отдельно проверить миграцию.
