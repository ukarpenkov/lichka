# Кнопки ±10 минут в DateTimePicker

**Статус:** idea — можно сделать позже, сейчас не планируется

## Название фичи

`datetime-picker-adjust-10-min` — в модалке кругового пикера даты/времени, по бокам от барабана часов/минут, две кнопки `−10` / `+10`, сдвигающие выбранный момент на 10 минут по календарю.

---

## Описание проблемы

DateTimePicker — основной способ задать время reminder / alarm / scheduled-сообщения (composer, редактор сообщения). Сейчас минуты меняются только барабаном `TimeScroller`: свайп или тап по соседнему значению (±1 мин за жест).

Для типичного сценария Lichka («напомни через ~10 минут», «сдвинь будильник на слот») это медленно: 10 отдельных шагов или долгий свайп с риском промахнуться. Кольца дней/месяцев и год при этом **не связаны** с барабаном времени: прокрутка минут `59 → 00` не переносит час, `23:59 → 00:00` не переносит день.

Нужен жест «сдвинуть *момент* на 10 минут», а не «подкрутить колесо минут».

---

## Что в коде сейчас (и почему исходный набросок не подходит)

Исходная идея предполагала единый `selectedDate`, `withSpring` в TimeScroller, `Layout.springify()` на кольцах, `IconButton` + lucide `Minus`/`Plus` и расширение сетки годов. Это не совпадает с виджетом.

| Как устроено | Следствие для фичи |
|--------------|-------------------|
| Состояние пикера — пять полей: `year`, `month`, `day`, `hour`, `minute` ([`DateTimePicker.tsx`](../../../src/widgets/datetime-picker/DateTimePicker.tsx)). Единого `selectedDate` нет. | Сдвиг минут считает родитель и расставляет поля, по тому же паттерну что `handleToday`. |
| `TimeScroller` — controlled: только `hour`/`minute` + `onHourChange`/`onMinuteChange`. Синхронизация с родителем уже есть (`useEffect` → `scrollToOffset`). | Кнопки **не** вызывают `scrollTo*` сами: достаточно сменить пропсы. Иначе снова риск Android-lockup (уже ловили). |
| Барабан — `FlatList` с 3 копиями 00–23 / 00–59, не Reanimated. Анимация = `scrollToOffset({ animated })`. `reduceMotion` уже гасит её. | Не тащить `withSpring` в TimeScroller. Для перехода `55 → 05` цель в *средней* копии на 50 позиций *назад* — визуально это «−50», не «+10». Нужно скроллить в соседнюю копию по знаку дельты, затем `recenter` без анимации (как после ручного свайпа). |
| Кольца дня/месяца крутятся через `dayRotation` / `monthRotation` + `withSpring(SPRING)` (`damping: 22`, `stiffness: 220`). `Layout.springify()` в пикере нет. | При смене дня/месяца — тот же `withSpring`, что у `handleToday` / swipe. Если поле не изменилось — кольцо не трогать. |
| Год жёстко `MIN_YEAR…MAX_YEAR` = 2020–2035 ([`YearPicker.tsx`](../../../src/widgets/datetime-picker/YearPicker.tsx), та же сетка в `YearGridModal`). Стрелки года на границе — no-op. | Не расширять сетку. Если `±10` вытолкнуло бы год за диапазон — no-op (кнопку приглушить). |
| Хаптик: `triggerHaptic()` уже проверяет `reduceMotion` **и** `getSettings().hapticEnabled`. Барабан тикает через `onTick={triggerHaptic}`. | Один вызов `triggerHaptic()` на тап кнопки. Не звать `hapticTap()` напрямую. При программном скролле глушить промежуточные `onTick`, иначе 10 вибраций за один тап. |
| `IconButton` — hit-area 48×48 + opacity-press, без смены цвета на accent. Lucide в UI нет: иконки — Streamline Pixel; `Minus` в наборе нет. | Компактный `Pressable` с текстом `−10` / `+10` шрифтом барабана (`monoWeight`), не иконка. |
| Колёса **зациклены независимо**: минуты не двигают часы, часы не двигают день, свайп месяца не меняет год. | `±10` — единственное место, где поля связаны. Это и есть ценность кнопок. |

`DateTimePickerModal` на `@react-native-community/datetimepicker` — **out of scope** (другой виджет, в composer не используется).

---

## Предлагаемое решение

### Поведение

Кнопки сдвигают **календарный момент** на ±10 минут. `Date` сам переносит минуты → часы → дни → месяцы → годы, включая конец месяца и високосный февраль:

| Было | Тап | Стало |
|------|-----|--------|
| 22:25 | `+10` | 22:35 (только минуты) |
| 22:55 | `+10` | 23:05 (час + минуты) |
| 23:55 | `+10` | 00:05 следующего дня |
| 31 авг 23:55 | `+10` | 1 сен 00:05 |
| 31 дек 23:55 | `+10` | 1 янв 00:05 следующего года |
| 01:05 | `−10` | 00:55 |
| 00:05 | `−10` | 23:55 предыдущего дня |
| 1 мар 00:05 | `−10` | 28 фев 23:55 (29 фев в високосный) |

Граница года:

- Результат с `getFullYear() < 2020` или `> 2035` → тап игнорируется, состояние не меняется.
- Кнопка, чей следующий шаг вышел бы за диапазон, `disabled` (цвет `text + '33'`, как стрелки года).

Остальной пикер без изменений: ручной свайп барабана по-прежнему **не** переносит соседние поля. Public API модалки (`visible` / `value` / `onConfirm` / `onCancel`) не меняется.

### UI

В ряду с центральной (выбранной) ячейкой барабана:

```
         21        24
   [−10]  22  :  25  [+10]
         23        26
```

- Текст `−10` / `+10`, `monoWeight('medium')`, размер ~15–16 — читается как подпись к минутам, без локализации.
- Покой: `text + '80'`. Press: accent `#4A9EFF` (как выбранные час/минута). Disabled: `text + '33'`.
- `hitSlop={8}`. Высота зоны ≈ `ITEM_HEIGHT` (46), без `minWidth/minHeight: 48` у `IconButton` — иначе кнопки раздуют `timeArea`.
- Вертикально — центр контейнера TimeScroller (`LIST_HEIGHT` = 3 × 46), то есть на линии highlight-бара.
- `accessibilityRole="button"`, label = видимый текст. Отдельные i18n-ключи в MVP не нужны.

### Математика

Чистая функция в [`circularMath.ts`](../../../src/widgets/datetime-picker/circularMath.ts) — рядом с `daysInMonth`, без UI:

```ts
export function shiftDateByMinutes(
  parts: { year: number; month: number; day: number; hour: number; minute: number },
  delta: number,
  bounds: { minYear: number; maxYear: number } = { minYear: MIN_YEAR, maxYear: MAX_YEAR },
): { year: number; month: number; day: number; hour: number; minute: number } | null {
  const next = new Date(parts.year, parts.month, parts.day, parts.hour, parts.minute);
  next.setMinutes(next.getMinutes() + delta);
  const y = next.getFullYear();
  if (y < bounds.minYear || y > bounds.maxYear) return null;
  return {
    year: y,
    month: next.getMonth(),
    day: next.getDate(),
    hour: next.getHours(),
    minute: next.getMinutes(),
  };
}
```

`setMinutes` закрывает переносы и високосные годы. Клиппинг — только год пикера, не «прижать к 1 янв 00:00» (скачок сюрприз). Сетку `YearGridModal` не расширять.

### Кто чем владеет

**`DateTimePicker.adjustMinutes(delta)`** (как `handleToday`):

1. `const next = shiftDateByMinutes({ year, month, day, hour, minute }, delta)`.
2. Если `null` — return.
3. `setYear/Month/Day/Hour/Minute`.
4. Кольца: если день/месяц изменились — `withSpring` к новому индексу; при `reduceMotionRef` — сразу, как в `handleCancel`. Год в шапке просто `setYear`.
5. `dayCountSV` обновить, если сменился месяц/год (уже есть эффект на `dayCount`).
6. `triggerHaptic()` один раз.

**`TimeScroller`** — только chrome кнопок:

- Новый опциональный колбэк `onAdjustMinutes?: (delta: number) => void`.
- Проп `canAdjust?: { minus: boolean; plus: boolean }` (считает родитель через пробный `shiftDateByMinutes`).
- Кнопки зовут `onAdjustMinutes(±10)` и **не** скроллят списки.
- При смене `hour`/`minute` извне: скролл в копию по знаку изменения (кратчайший путь с учётом 3 копий), затем существующий `recenterHours` / `recenterMinutes` без анимации.
- На время программного скролла не вызывать `onTick`.
- `reduceMotion` — как сейчас: `animated: false`.

Шаг `10` — константа рядом с `TimeScroller` (`ADJUST_MINUTES = 10`), не настраивается в MVP.

### Анимации (спека 6.5, но паттерны пикера)

| Что изменилось | Анимация |
|----------------|----------|
| Только минуты (и час, если перенос) | `FlatList.scrollToOffset`, не Reanimated |
| День и/или месяц | `withSpring` на `dayRotation` / `monthRotation`, `SPRING` как у колец |
| Год | без анимации (как стрелки YearPicker) |
| `reduceMotion` | мгновенно и кольца, и барабан; хаптик и так выключен |

## Альтернативы

| Вариант | Решение |
|---------|---------|
| Свести стейт пикера к одному `Date` | Отклонено: слишком большой рефактор ради двух кнопок; кольца и барабан уже живут на отдельных полях |
| `±10` только крутит минуты с wrap `55→05` без часа | Отклонено: почти то же, что свайп барабана, и ломает ожидание «через 10 минут» |
| `IconButton` + pixel `Plus` / нет `Minus` | Отклонено: 48dp ломает компактный барабан; иконка не говорит «10 минут» |
| lucide-react-native | Отклонено: в UI уже pixel-иконки, для двух подписей зависимость не нужна |
| Расширять 2020–2035 при переносе года | Отклонено: ломает контракт YearPicker / YearGridModal |
| Клиппить к `2020-01-01 00:00` / `2035-12-31 23:50` | Отклонено: неожиданный скачок; у стрелок года уже no-op |
| Long-press repeat (как зажим стрелок) | Out of scope MVP; при необходимости отдельно |
| Шаг 5 минут (как пресет PeriodPicker) | Отклонено: 10 — компромисс между «скоро» и числом тапов; 5 слишком мелко рядом с барабаном ±1 |

## Оценка сложности

| | |
|--|--|
| Время | ~0.5–1 день: хелпер + кнопки + направленный скролл барабана + смоки переносов |
| Риски | Программный `scrollToOffset` на Android (история lockup / неверного центра); лишние `onTick` на промежуточных индексах; визуальный скролл «не в ту сторону» при wrap, если целиться в среднюю копию; частые тапы, пока барабан ещё едет |
| Тесты | Юнит на `shiftDateByMinutes`: час, сутки, 31 авг, 31 дек, 1 мар / високосный, границы 2020 и 2035 → `null`. UI-тестов на пикер нет — не плодить RTL на Modal+RNGH в MVP, если хелпер покрыт |

## Критерии приёмки (если когда-нибудь возьмём в работу)

- [ ] `+10` / `−10` сдвигают момент на 10 минут с переносом часа/дня/месяца/года
- [ ] 31 дек 23:55 +10 → 1 янв 00:05; 1 мар 00:05 −10 → 28 или 29 фев 23:55
- [ ] На `2020-01-01 00:05` кнопка `−10` неактивна; на `2035-12-31 23:55` — `+10`
- [ ] Барабан доезжает до новых часа/минут; при wrap минут скролл по знаку дельты, не на 50 позиций назад
- [ ] Кольца дня/месяца анимируются только если значение изменилось; при reduceMotion — мгновенно
- [ ] Один haptic на тап (если haptic включён и reduce motion выключен)
- [ ] Ручной свайп барабана по-прежнему не переносит день
- [ ] API `DateTimePicker` без breaking changes

---

## Почему отложено

Улучшение UX, не блокер. Барабан уже закрывает сценарий, пусть и медленнее. Реализация потребует аккуратной работы с программным скроллом на Android — есть история багов в `TimeScroller`.

Если вернёмся к идее: перенести в `docs/features/datetime-picker-adjust-10-min-proposal.md`, статус `draft` → обсуждение → `approved` → реализация.
