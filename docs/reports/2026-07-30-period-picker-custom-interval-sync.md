# Синхронизация custom interval с пресетами PeriodPicker

**Дата:** 2026-07-30
**Промпт/задача:** На странице периодических напоминаний визуально заполнять custom interval выбранным дефолтным интервалом с кнопок; единица остаётся в минутах (пересчёт hour/day → минуты). Proposal: `docs/features/period-picker-custom-interval-sync-proposal.md`.

## Что сделано
- При нажатии на пресет поле custom interval заполняется значением пресета в минутах (`5` / `10` / `15` / `60` / `1440`).
- При открытии пикера с уже выбранным пресетным `value` то же значение сразу показывается в custom-поле.
- Ручной ввод по-прежнему сбрасывает выделение пресета; подтверждение без изменений (`selected ?? customMinutes`).

## Изменённые файлы
- `src/widgets/period-picker/PeriodPicker.tsx` — `handlePresetPress` и инициализация при `visible` пишут `String(minutes)` в `customText` вместо очистки
- `docs/features/period-picker-custom-interval-sync-proposal.md` — proposal фичи

## Принятые решения
- Единица custom-поля не меняется: всегда минуты, hour/day — только пересчёт (`60` / `1440`).
- Не трогали API `onConfirm` и хранение интервала — только визуальный sync UI-state.

## Известные ограничения
- `maxLength={4}` по-прежнему ограничивает ввод; `1440` укладывается.
- Нет отдельной подписи «= N min» у пресетов — достаточно заполненного поля.

## Тестирование
- [ ] Выбрать «Every 15 min» → в custom interval `15`
- [ ] Выбрать «Every hour» → `60`; «Every day» → `1440`
- [ ] После выбора пресета вручную изменить число → пресет снимается, Done сохраняет введённые минуты
- [ ] Открыть пикер с уже сохранённым интервалом `60` → активен «Every hour», в поле `60`
