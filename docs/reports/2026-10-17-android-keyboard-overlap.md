## Принятые решения
- Использовать системные IME insets и пересечение с реальным контейнером вместо списка марок устройств или дополнительных фиксированных поправок.
- Не менять глобальный `adjustNothing` Activity: изменение этого режима могло бы нарушить работающие экраны. Нативные Modal сохраняют собственный режим окна.
- На Android 11+ границы окна берутся из WindowMetrics; на более старых версиях используется видимая область окна. Insets читаются непосредственно у View в соответствующем окне.
- Датчик наблюдает отрисовку и отправляет событие только при изменении перекрытия. Измеряемая внешняя область не уменьшается от собственного spacer, что предотвращает цикл повторной компенсации.
- Не добавлять производственную библиотеку для клавиатуры. Общая UI-механика находится в shared; страницы и виджеты используют public API shared/ui.
- Проверено поведение установленного React Native 0.85.3: основной keyboard event вычитает нижнюю системную панель из IME-высоты и реагирует на смену видимости. Для понимания ограничений сверены [документация Keyboard](https://reactnative.dev/docs/keyboard.html) и [рекомендации Android по IME insets](https://developer.android.com/develop/ui/views/layout/sw-keyboard).

## Известные ограничения
- Исходный Realme физически недоступен; точная модель (возможно GT 7T), Android и версия клавиатуры неизвестны. Нельзя утверждать, что баг подтверждённо устранён на всех прошивках BBK, Pixel и Xiaomi.
- Проверка интерфейса выполнена на эмуляторе Small_Phone, 720×1280, плотность 320 dpi, API 37, Gboard. Android 10 и старше, iOS, реальные OEM-прошивки, split-screen и поворот требуют ручной проверки. Геометрия поворота/split-screen покрыта unit-тестами, что не заменяет устройство.
- Для плавающей клавиатуры с нулевым нижним IME inset контейнер не поднимается: произвольное положение плавающего окна Android этим API не предоставляет.
- На очень низком экране все поля одновременно могут не помещаться: предусмотрена прокрутка содержимого, кнопки сохраняются в доступной области.
- Визуальная проверка остальных экранов не равна полной сертификации приложения на всех размерах экрана. Редактор и поиск дополнительно требуют проверки на целевых устройствах.
- Для проверки изменений нужна новая Android-сборка: одной перезагрузки JavaScript недостаточно, поскольку добавлен нативный компонент.
