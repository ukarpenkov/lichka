# Баг: Системный экран настроек батареи открывается при повторной постановке будильника

**Дата:** 2026-09-19
**Severity:** Medium
**Платформа:** Android (воспроизведено на Xiaomi/MIUI, но затрагивает все вендоры)
**Статус:** fixed

## Описание

При постановке будильника приложение уводит пользователя на системный экран «Сведения о батарее» (`ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`), чтобы тот выбрал «Нет ограничений». Экран открывается даже когда исключение из оптимизации батареи **уже выдано** — то есть делать там нечего.

## Ожидаемое поведение

Системный экран открывается только пока приложение реально под ограничениями батареи. Если «Нет ограничений» уже выставлено, постановка будильника проходит без ухода из приложения.

## Фактическое поведение

Первый будильник после каждого запуска приложения открывает системный экран независимо от текущего состояния разрешения. Пользователь возвращается назад, ничего не меняя.

## Шаги воспроизведения

1. Поставить будильник, на системном экране выбрать «Нет ограничений»
2. Полностью закрыть приложение и открыть заново
3. Поставить ещё один будильник
4. Факт: снова открывается системный экран батареи, хотя ограничений уже нет

## Корневая причина

`src/features/notifications/requestExactAlarmPermission.ts` защищался только module-scope флагом `batteryOptimizationRequested`. Флаг живёт в памяти JS-бандла и сбрасывается при каждом запуске приложения, а фактическое состояние разрешения не проверялось вообще — нативного метода для такой проверки не было. В итоге «спрашиваем один раз» означало «один раз за сессию», а не «один раз, пока разрешение не выдано».

## Решение

Добавить в `NotificationModule` проверку `PowerManager.isIgnoringBatteryOptimizations(packageName)` и в JS вызывать системный экран только если проверка вернула `false`. API стандартный для Android (с API 23), поэтому поведение одинаково на всех вендорах, а не только на Xiaomi. Флаг сессии остаётся как защита от повторного открытия экрана при отказе пользователя в рамках одного запуска.

## Изменённые файлы

- `android/app/src/main/java/com/lichka/NotificationModule.kt` — метод `isIgnoringBatteryOptimizations()`
- `src/shared/lib/notificationChannels.ts` — JS-обёртка
- `src/features/notifications/requestExactAlarmPermission.ts` — проверка состояния перед запросом
- `src/widgets/message-composer/MessageComposer.tsx` — `await` на ставшем асинхронным запросе
