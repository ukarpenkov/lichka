# [UI] Клавиатура самопроизвольно закрывается после фокуса поля сообщения

**Модуль:** `src/pages/chat-room/ChatRoomScreen.tsx`, `src/widgets/message-composer/MessageComposer.tsx`
**Платформа:** Android (воспроизводится и потенциально на iOS)
**Приоритет:** P0
**Воспроизводимость:** 100%

## Описание

На экране чата при тапе по полю `Message...` клавиатура открывается, примерно через секунду закрывается без действия пользователя, а поле теряет фокус. Повторный тап запускает тот же цикл, поэтому ввести сообщение невозможно.

## Шаги воспроизведения

1. Открыть любой чат, например `Saved`.
2. Тапнуть по полю ввода `Message...`.
3. Не выполнять других действий.

## Фактический результат

Клавиатура открывается и почти сразу закрывается, поле ввода теряет фокус.

## Ожидаемый результат

Клавиатура и фокус сохраняются, пока пользователь сам не закроет клавиатуру, не покинет экран или не отправит сообщение.

## История исправлений

### Попытка 1 (2026-08-07) — недостаточно

Композер условно оборачивался в `GestureDetector` только при `atBottom === true`. Открытие клавиатуры меняло метрики списка → `atBottom` мерцал → иерархия `GestureDetector → MessageComposer` то появлялась, то исчезала → remount `TextInput` → потеря фокуса.

Фикс: native-обёртка композера сделана постоянной. Регрессия remount закрыта тестом, но на устройстве баг остался.

### Корневая причина (актуальная)

Future Peek pan (`GestureDetector`) оборачивал **всю** `chatArea`, включая `MessageComposer`, и через `blocksExternalGesture(composerNativeGesture)` блокировал Native-жест композера на каждое касание, пока pan в состоянии `BEGAN`.

При тапе по `Message...`:

1. Фокус и клавиатура успевают открыться (нативный `EditText`).
2. Одновременно pan entry-жеста участвует в touch arena / layout lift над клавиатурой.
3. Фокус с поля слетает, клавиатура закрывается. Цикл повторяется на каждый тап.

Дополнительно entry-peek был разрешён при открытой клавиатуре, что усиливало конфликт.

## Исправление

1. **`MessageComposer` вынесен из зоны entry-peek pan** — `GestureDetector` оборачивает только список; композер остаётся sibling списка **внутри** `peekHost` (чтобы flex-высота FlatList оставалась ограниченной viewport’ом).
2. **Entry-peek отключён при открытой клавиатуре** (`!keyboardOpen`), чтобы pan не конкурировал с вводом.
3. **`TextInput` композера** снова из `react-native` (не RNGH) — поле больше не обязано жить внутри gesture tree.
4. На history `FlatList` — `keyboardShouldPersistTaps="handled"`.
5. У list-обёрток — `minHeight: 0`, чтобы Yoga сжимала список при `paddingBottom` клавиатуры.

Peek из области списка при закрытой клавиатуре и `atBottom` сохраняется. Свайп из самого поля ввода в Future намеренно убран.

### Регрессия после первой итерации фикса фокуса

Композер вынесли sibling’ом `peekHost` (рядом с `GestureDetector` внутри `chatArea`). Без ограниченного flex-родителя FlatList раздувался по высоте контента, `overflow: hidden` клипил верх ленты, `scrollEnabled` оставался false — до первого сообщения нельзя было доскроллить. Исправлено возвратом композера внутрь `peekHost` (вне pan) + `minHeight: 0`.
