# Не запускается запись голоса и нативный краш DatePicker

**Статус:** исправлено

## Симптомы

- После долгого нажатия на микрофон срабатывала вибрация, но запись не начиналась.
- При отказе в доступе к микрофону или ошибке запуска пользователь не видел объяснения.
- На Android DatePicker мог медленно закрываться или не реагировать на возврат.
- В версии 4.0 наблюдался нативный краш в `libhermesvm.so` / `libworklets.so` при выполнении callback из UI worklet.

## Причины

1. В `AndroidManifest.xml` не было разрешения `android.permission.RECORD_AUDIO`. Запрос разрешения завершался отказом, который интерфейс молча игнорировал.
2. Вибрация запускалась до проверки разрешения и фактического старта записи, поэтому ошибочно сигнализировала об успехе.
3. Проект использовал `react-native-worklets` 0.10.0. В этой версии была ошибка времени жизни remote callback при переходе из worklet в RN/Hermes runtime. Стек из отчёта соответствует этому пути: Hermes call → Worklets → `RuntimeScheduler_Modern::executeTask`.
4. При закрытии DatePicker синхронно выполнялся полный сброс локального состояния и shared values, а жесты оставались включёнными до закрытия Modal.

## Исправление

- Добавлено Android-разрешение `RECORD_AUDIO`.
- Проверка и запрос разрешения защищены обработкой ошибок; на других платформах Android API не вызывается.
- Вибрация подтверждает только успешно начатую запись.
- Добавлены понятные диалоги для запрета доступа и ошибки запуска записи.
- Reanimated/Worklets обновлены до совместимых исправленных патч-версий; Babel использует актуальный Worklets plugin.
- DatePicker закрывается сразу, отключает жесты в скрытом состоянии и сбрасывает transient-состояние без тяжёлого восстановления значений во время закрытия.

## Проверка

- Unit-тест запроса разрешения микрофона.
- Component-тесты успешного старта записи, отказа в разрешении и ошибки старта.
- Component-тест аппаратного возврата из DatePicker.
- Полный Jest, ESLint и Android debug build.
