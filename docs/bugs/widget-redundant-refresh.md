# Виджет повторно рисует неизменный фон

**Дата:** 2026-10-22
**Статус:** in progress

## Проблема

`ScheduledScreen` периодически отправляет snapshot; `WidgetModule` сохраняет его и всегда вызывает полное обновление. `ScheduledWidgetProvider` заново создаёт bitmap и PNG даже при тех же размере/цветах, а `refreshAllNow` повторно уведомляет список после уведомления внутри `updateWidgetInner`. XML дополнительно задаёт обновление каждые 30 минут. При срабатывании уведомления без открытого приложения устаревшие одноразовые записи не удаляются из видимого списка.

## Ожидаемое поведение

Изменения snapshot обновляют список, повтор неизменных данных не вызывает перерисовку. Оформление обновляется по событиям темы/языка/размера; PNG повторно используется. Срабатывание напоминания обновляет список без запуска JS и без polling.

## Дополнительная причина устаревшего оформления

На эмуляторе API 37 воспроизведён возврат предыдущего языка/темы после resize. В Android `AppWidgetManager.notifyCollectionWidgetChange` асинхронно получает старые RemoteViews, конвертирует legacy-коллекцию и позже повторно публикует весь старый кадр. Это конкурирует с полным обновлением темы. Для API 31+ используется `RemoteCollectionItems`: список и оформление отправляются единым snapshot, а изменения только списка — через `partiallyUpdateAppWidget`. Старый сервис остаётся для API 24–30.
