# Меню сообщения (Edit/Delete) иногда не открывается после переключения вкладок

**Дата:** 2026-08-05  
**Статус:** fixed

## Описание

На экране чата долгий тап по сообщению обычно открывает модальное меню с действиями Edit / Delete. После нескольких переходов во вкладку Scheduled / режим future и обратно меню может перестать появляться.

## Шаги воспроизведения

1. Открыть чат.
2. Зажать сообщение — меню Edit/Delete появляется.
3. Перейти во вкладку Scheduled / future.
4. Вернуться обратно в чат.
5. Повторить переходы несколько раз.
6. Снова зажать сообщение.

## Ожидаемый результат

Меню сообщения стабильно открывается при каждом long-press, независимо от предыдущих переходов между вкладками / режимами.

## Фактический результат

Модальное меню может не появиться (или мелькнуть и сразу закрыться).

## Окружение

- `src/pages/chat-room/MessageContextMenu.tsx`
- `src/pages/chat-room/ChatRoomScreen.tsx`
- `src/pages/chat-room/MessageLine.tsx` / `FutureTimeline.tsx`

## Причина

1. **Ghost-close через backdrop.** После открытия меню пункты Edit/Delete были `disabled={!armed}` (~350 ms), чтобы не ловить ghost-click с long-press. Disabled-дочерний `Pressable` не перехватывает touch — отпускание пальца над карточкой меню уходит в backdrop `onPress={onClose}` и сразу закрывает меню. В Future / после скролла строка чаще под центром экрана (где рисуется меню), поэтому баг проявляется нестабильно и чаще после переключений history ↔ future.
2. **Modal + blur.** При уходе с экрана (Scheduled / другой tab) `menuMessage` не сбрасывался. RN `Modal` мог остаться в `visible=true` в React-state при сломанной нативной презентации — следующий long-press не переоткрывал меню.

## Решение

- Backdrop закрывает меню только после arm; пункты меню не `disabled`, а игнорируют press до arm (touch не пробивает к backdrop).
- Карточка меню обёрнута в поглощающий `Pressable`.
- На `blur` / смене timeline mode меню сбрасывается; при открытии — новый `menuKey` для remount Modal.
- В меню добавлен пункт **Copy** выше Edit.
